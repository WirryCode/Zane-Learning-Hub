Images

img, alt, srcset, picture, figure

Images that carry information (content) belong in HTML with <img>. Purely decorative images (gradients, page backgrounds) belong in CSS. This module is a tour of the essentials: src, alt, responsive images and performance attributes.

1. The two required attributes

<img src="images/eve.png" alt="Eve, the probe droid">
  • src: the image URL. Without it there is nothing to render.
  • alt: a text alternative, used by screen readers, search engines, voice assistants, and shown if the image fails to load. It is also valuable in HTML emails where images are often blocked.
  • <img> is a void element. <img ... /> is XML style; in HTML the slash does nothing.

2. Writing good alt text

Imagine reading the page aloud to a friend who cannot see it. Convey what the image means in this context, concisely, and nothing the surrounding text already says.

Icon (magnifier, house, floppy disk)The meaning: alt="Search", alt="Home", alt="Save"

Purely decorative, or repeats nearby textalt="" (empty, but present)
  • Do not start with "image of" or "photo of": the <img> role already says so (unless the medium matters, e.g. "oil painting").
  • Match the tone of the site. Keep it short and precise.
  • Empty alt="" tells assistive tech to skip the image. A missing alt is worse: many screen readers read out the file name.
  • If you use non-standard icons, add a visible legend: do not make icons the only way to understand the UI.

3. Responsive images

Do not send a phone a desktop-sized file, but do give high-density screens sharper ones. Two tools:

<!-- A) srcset + sizes: same picture, different file sizes -->
<img src="eve-400.jpg" alt="Eve"
     srcset="eve-400.jpg 400w, eve-800.jpg 800w"
     sizes="(max-width: 800px) 100vw, 800px">

<!-- B) picture: art direction and format fallback -->
<picture>
  <source srcset="eve.avif" type="image/avif">
  <source srcset="eve-wide.jpg" media="(min-width: 800px)">
  <img src="eve.jpg" alt="Eve">
</picture>

  • One srcset attribute per <img>, holding a comma-separated list of "URL descriptor" pairs.
  • sizes describes how wide the image will be displayed, so the browser can choose among w candidates. If omitted it assumes 100vw.
  • <picture> takes any number of <source> elements and exactly one required <img>, the fallback and the element that carries alt.
🧠 Remember itPAF: picture vs srcsetPenguins Adore Fish = Picture is for Art direction and Formats. srcset is for sizes and resolution.

4. Performance attributes

  • width and height: unitless pixel values give the browser the aspect ratio, so space is reserved before the image loads and the page does not jump (layout shift). CSS such as img { max-width: 100%; height: auto } still makes the image responsive.
  • loading="lazy" defers off-screen images until they are near the viewport. Default is eager. If JavaScript is disabled, images load eagerly.
  • Also available: decoding="async", fetchpriority="high", crossorigin, referrerpolicy.
  • ismap (server-side image maps) is rare; the <img> must sit inside a link. <input type="image"> sends click x and y automatically.
⚡ Pro hackMind the missing sizeAdd width and height to every <img> even when CSS resizes it. It is the cheapest layout-shift fix there is.
⚡ Pro hackFormat fallback for free<picture> with type="image/avif" then type="image/webp" then a JPEG <img> lets modern browsers pick the smallest file you ship.
☠ Major fail pointLazy-loading the hero imageloading="lazy" on the top banner delays your biggest visible image. Lazy-load below-the-fold images only.
☠ Major fail pointText baked into imagesA banner image containing words fails zoom, translation and screen readers unless the alt repeats every word. Use real text over the image.

5. figure and figcaption

<figure> wraps self-contained content, an image, code, a quote or a diagram, with an optional <figcaption>. The caption must be the first or last child of the figure.
