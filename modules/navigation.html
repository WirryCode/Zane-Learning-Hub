Navigation

nav, menus, skip links

Navigation is a group of links that helps users move around. There are no strict rules for how it looks, but how it is marked up decides whether everyone can use it.

1. Types of navigation

TypePurpose
GlobalTop-level pages; identical on every page
LocalLinks within the current section or page
BreadcrumbWhere this page sits in the site hierarchy
Table of contentsJump links to headings on this page
Site mapHierarchical links to every page
Skip linkBypass repeated blocks to reach <main>

Goal: any page in as few clicks as possible, without overwhelming the user. Footers should also be identical on every page, but they do not have to mirror global navigation.

2. The nav landmark and its name

<nav> has the implicit role navigation, a landmark. Use it for major blocks of links only. Name each one when there is more than one.

<!-- Visible heading exists: point at it -->
<nav aria-labelledby="tocTitle">
  <p id="tocTitle">On this page</p>
  <ul>
    <li><a href="#types">Types</a></li>
    <li><a href="#skip">Skip links</a></li>
  </ul>
</nav>

<!-- No visible text: use aria-label, WITHOUT the word "navigation" -->
<nav aria-label="Primary"> ... </nav>
  • aria-labelledby reuses visible text (best: one source of truth). aria-label is hidden text.
  • Screen readers already say "navigation", so aria-label="Primary" not "Primary navigation".
  • Put links in a <ul> so users hear "list, 5 items".
⚠ Common mistakeEverything is a navWrapping every link cluster in <nav> floods the landmark list. Reserve it for major blocks (primary, breadcrumb, table of contents, footer groups).
⚠ Common mistakeNaming it "navigation"aria-label="Main navigation" is announced "Main navigation navigation". Name the purpose only.

3. Skip link

A "Skip to main content" link, first in the focus order, lets keyboard users bypass the repeated header and menu. It may be hidden visually, but it must become visible when focused.

⚡ Pro hackMake the target focusableGive the skip target tabindex="-1" (<main id="main" tabindex="-1">). Focus then really moves there in every browser, not just the scroll position.
☠ Major fail pointHidden skip link that can't be focuseddisplay:none or visibility:hidden removes it from the tab order, so it never appears. Hide by moving off-screen, then reveal on :focus.

4. Breadcrumbs and the current page

  • Use <nav aria-label="Breadcrumbs"> containing an ordered list (the order matters).
  • Separators are decoration: add them with CSS li + li::before so screen readers do not read them. Keep contrast adequate.
  • If the current page is included, make it plain text and add aria-current="page". Do the same for the current link in global or local navigation.
  • Breadcrumbs show hierarchy, not the path the user clicked through; do not label click-history as breadcrumbs.
🧠 Remember itONA: breadcrumb recipeOctopuses Nap Alot = Ol inside a Nav, with Aria-current on the current item.
🧠 Remember itLLAMA: good nav checklistLabel it, List it, Aria-current the page, Mark it with <nav>, Always the same on every page (global).
⚡ Pro hackStyle from the attributenav a[aria-current="page"] { font-weight: 700 } styles the current link straight from the accessibility attribute. No extra class to forget.

5. Keep order predictable

Layouts may change with the viewport, but tab order should not surprise people. Do not ship two copies of the navigation and hide one. Keep one nav in the DOM and let CSS move it, as long as DOM order still makes sense.
