Details & Summary

Disclosure widgets, accordions

An expander arrow (a disclosure widget) hides and shows content. Stack several and you get an accordion, the classic home of the FAQ page. Before HTML had this, developers faked it with a <label> and a hidden checkbox plus the CSS :checked + div trick, or with a JavaScript library. Today <details> and <summary> do it natively, with keyboard support and no script, and have been supported in every modern browser since January 2020.

1. The two elements

  • <details> is the container. <summary> is its always-visible label (a legend or caption) and acts as the button.
  • A click, a tap, or pressing Enter or Space on a focused <summary> toggles the rest of the contents.
  • <summary> must be the first child of <details>. Its content is plain text or phrasing content (what fits in a paragraph), optionally with heading content.
  • Everything else in <details> is the hidden/shown content.
<details>
  <summary>What is the return policy?</summary>
  <p>Return it within 30 days, unused, with the receipt.</p>
</details>

2. The open attribute

  • open is a boolean. Present (with any value, or none) means the contents are shown; absent means only the <summary> shows.
  • The browser adds and removes open itself as the user clicks, so you can style by state: details[open].
  • Write open in your HTML to start expanded. Leave it out to start collapsed.
  • The collapsed content is still in the DOM: it is just not rendered. Scripts can read it, and in some browsers (Chrome, Edge) find-in-page opens a closed <details> that contains the match. Firefox and Safari behaviour has differed, so never depend on it.

3. Exclusive accordions with name

Give several <details> the same name and they behave like radio buttons: opening one closes the others. This is the no-JavaScript accordion, supported in current Chrome, Safari and Firefox.

<details name="faq" open><summary>Shipping</summary><p>3 to 5 days.</p></details>
<details name="faq"><summary>Returns</summary><p>30 days.</p></details>
<details name="faq"><summary>Warranty</summary><p>1 year.</p></details>
  • The group is formed by the shared name, across the whole document (or shadow tree). Give each accordion its own name.
  • If two members have open in the HTML, the browser keeps only one open.
  • Older browsers ignore name and simply let every item open independently. That is graceful degradation, not a bug.

4. Styling the marker

  • The triangle is the <summary>'s marker, treated like a list-item marker. Change it with list-style (list-style-type, list-style-image) or style summary::marker, which accepts only a few properties (colour, font size, content).
  • Common practice: hide the marker (list-style: none, plus summary::-webkit-details-marker { display: none } for older Safari), then draw your own with summary::before and rotate it for details[open] summary::before.
  • Changing summary { display: flex } removes the marker in some browsers: another reason to draw your own icon.
  • Always keep a visible indicator that the summary expands. Never remove it without replacing it.
  • Add cursor: pointer, spacing between items, and a transition on the icon's rotation. Newer CSS (details::details-content, interpolate-size) can animate the height too; treat it as progressive enhancement.
summary { list-style: none; cursor: pointer; }
summary::-webkit-details-marker { display: none; }
summary::before { content: "▶"; display: inline-block; margin-right: .5em; transition: transform .2s; }
details[open] > summary::before { transform: rotate(90deg); }

5. How errors are handled

  • No <summary>: the browser inserts its own with the word "Details". It lives in a shadow root, so your summary CSS does not touch it. Always write one.
  • <summary> not first: browsers still use the first <summary> child, but the HTML is invalid. Put it first.
  • Interactive content inside a summary (a link, a <label>, a button) is allowed to parse but browsers disagree on focus and clicks: some tab to both, some toggle when the label is clicked. Avoid it.
  • <summary> has the implicit role of a button (with expanded/collapsed state) and <details> is a group. Headings inside a summary may lose their heading role for screen readers because a button's children are presentational: test, or put the heading outside.
  • Keyboard focus into <summary> varies by browser setting (Safari's "Press Tab to highlight each item" option is a classic surprise). Test with the keyboard.

6. The HTMLDetailsElement interface

  • el.open is a boolean reflecting the open attribute: read it, or set el.open = true to expand.
  • The toggle event fires after the state changes, whichever way it changed (click, script, or find-in-page). Read el.open inside it. A beforetoggle event fires first in newer browsers. Listen with addEventListener('toggle', ...).
  • toggle does not bubble: attach it to each <details> (or use capture on a parent).
  • Newer CSS offers details:open as a pseudo-class; [open] works everywhere.
