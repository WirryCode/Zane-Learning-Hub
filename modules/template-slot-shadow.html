Template, Slot & Shadow

Web components basics

Web components let you build a UI widget once and reuse it like any built-in element. They need JavaScript to define, but no library. The standard has three parts that work together: HTML templates (<template>, <slot>), custom elements (customElements.define) and the shadow DOM (attachShadow). Together they give you self-contained, encapsulated, reusable elements. In this module we build a <star-rating> element.

1. The template element

  • <template> declares a fragment of HTML that is not rendered and is cloned into the page with JavaScript.
  • Its content is inert: images do not load, scripts do not run, styles do not apply until the clone is inserted into a live document.
  • The children are not children of the <template> in the DOM. They live in a DocumentFragment returned by template.content.
  • Appending that content to the page makes it part of the normal, styleable DOM. That alone is not a custom element.
<template id="star-rating-template">
  <form>
    <fieldset>
      <legend>Rate your experience:</legend>
      <input type="radio" name="rating" value="1" aria-label="1 star" required>
      <input type="radio" name="rating" value="2" aria-label="2 stars">
      <input type="radio" name="rating" value="3" aria-label="3 stars">
    </fieldset>
    <button type="reset">Reset</button>
  </form>
</template>
<script>
  const tpl = document.getElementById('star-rating-template');
  document.body.appendChild(tpl.content.cloneNode(true)); // clone, never move the original
</script>
  • cloneNode(true) (deep clone) lets you reuse the template as many times as you like. Appending tpl.content directly moves it, and it is then gone for the next use. document.importNode(tpl.content, true) is the equivalent that also adopts the nodes into the document.

2. The slot element

A <slot> is a placeholder inside a shadow tree. Elements you write between the tags of the custom element are inserted into matching slots.

  • A named slot (<slot name="legend">) receives children with a matching slot="legend" attribute. The slot attribute is global and must be on a direct child of the host.
  • An unnamed <slot> is the default slot: it receives every child (and text) that has no slot attribute.
  • Content inside the <slot> element is the fallback, shown when nothing is assigned.
  • Children that match no slot (and there is no default slot) stay in the DOM but are not rendered.
  • Slotted content is not copied: it stays in the normal ("light") DOM, which is why page CSS still styles it.
<star-rating>
  <span slot="legend">Blendan Smooth</span>
</star-rating>
<star-rating></star-rating>   <!-- shows the fallback legend -->

3. Undefined and unknown elements

  • Browsers never fail on an element they do not recognise: it becomes an anonymous inline element with no styles or semantics, like a <span>.
  • <rating> (no hyphen) is a true unknown element (HTMLUnknownElement). <star-rating> is a valid custom element name that is merely not yet defined: it is a plain HTMLElement until you call customElements.define. The CSS pseudo-class :defined matches once it is upgraded.
  • Until it is defined, its children render like they would in a <span>.

4. Custom elements

customElements.define('star-rating', class extends HTMLElement {
  constructor() {
    super();                                   // always call super() first
    const tpl = document.getElementById('star-rating-template').content;
    const root = this.attachShadow({ mode: 'open' });
    root.appendChild(tpl.cloneNode(true));
  }
});
  • The name must contain a hyphen and be lowercase (star-rating, x-card). A name without a hyphen throws; it is reserved for built-in elements.
  • customElements.define(name, class) can run only once per name. customElements.get(name) checks, and customElements.whenDefined(name) returns a promise.
  • The browser attaches a shadow tree to each <star-rating> and puts a clone of the template in it. The element's own children are not replaced: they stay in the light DOM and are rendered only where a slot picks them up.
  • Lifecycle callbacks: connectedCallback, disconnectedCallback, attributeChangedCallback (with static get observedAttributes()), adoptedCallback. Do heavy work in connectedCallback, not the constructor.
  • attachShadow() works only on autonomous custom elements and a short list of built-ins (<div>, <span>, <p>, <section>, <article>, <aside>, <nav>, <header>, <footer>, <main>, <blockquote>, headings, <body>). Not on <input>, <img>, <a>, <button>.

5. Shadow DOM and encapsulation

  • The shadow host is the element the shadow DOM is attached to. The shadow root is the root of the shadow tree. The boundary between shadow and regular DOM can be crossed, but only on purpose.
  • Styles are scoped: page CSS does not reach inside, and the component's <style> does not leak out. That means you can use short selectors such as input instead of input[type="radio"].
  • Radios styled by the page stylesheet "go back to plain radios" inside a component for exactly this reason: page CSS no longer applies.
  • mode: 'open' makes the root reachable as el.shadowRoot. mode: 'closed' makes el.shadowRoot return null; it is a convenience, not a security feature.
  • Elements inside a shadow tree are hidden from document.querySelector. Query el.shadowRoot.querySelector(...) instead.
  • Form controls inside a shadow tree are not part of the surrounding form. To take part in a form, a custom element must be form-associated (static formAssociated = true and ElementInternals).
