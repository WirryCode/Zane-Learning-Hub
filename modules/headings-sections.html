Part 1 · Module 03

Headings & Sections

Landmarks, header, footer, main, article, section

1. Why semantic structure beats divs

Compare three ways to build the same site header. All can look identical with CSS, but only the last tells browsers, search engines and screen readers what everything is.

<!-- 1. Div soup: no meaning, needs ids/classes + comments -->
<div id="pageHeader">
  <div id="title">Machine Learning Workshop</div>
  <div id="navigation"> ...links... </div>
</div> <!-- end header -->

<!-- 2. Roles added: meaning, but verbose -->
<div role="banner">
  <div role="heading" aria-level="1">Machine Learning Workshop</div>
  <div role="navigation"> ...links... </div>
</div>

<!-- 3. Semantic: meaning for free, no classes needed -->
<header>
  <h1>Machine Learning Workshop</h1>
  <nav> ...links... </nav>
</header>

The semantic version needs no id or class hooks, and you can style it with low-specificity selectors such as header nav a.

🧠 Remember itHNMAF: the page skeletonHungry Ninja Munches All Food = Header, Nav, Main, Aside, Footer.

2. Header and footer: sometimes landmarks

ElementWhere it sitsRole
<header>Top level of <body>banner landmark (site header)
<header>Inside main, article, sectionNo landmark: just that section's header
<footer>Top level of <body>contentinfo landmark (copyright, contact, policies)
<footer>Inside article, aside, main, nav, sectionNo landmark

<address> is for contact details of a person or organisation (usually in a footer). Despite its name, it is not for any postal address you want to display.

⚠ Common mistakeOne header per pageWrong: a page may have many <header> and <footer> elements (one per article, for example). Only the top-level ones are landmarks.

🧠 Remember itASA test: article or section?Could it live Alone on another site? Yes → <article>. Is it a Subdivision of a bigger piece with a heading? → <section>. Is it just Appearance/layout? → <div>.
☠ Major fail pointSection with no headingA <section> should almost always have a heading. A section without one is usually a <div> in disguise. If you only need a styling wrapper, use <div>.
⚠ Common mistakeMany mainsUsing <main> for every page region. The spec allows one visible <main> per page; extra ones must carry the hidden attribute. (The notes say "one"; the nuance is that hidden extras exist for single-page apps.)

4. Nesting: how headings fit the structure

  • A heading in the top-level <header> names the site or application.
  • A heading in <main> names that page.
  • A heading in an <article> or <section> names that subsection.
  • Use levels like a word processor: <h1> then <h2> then <h3>. Do not skip levels.

Example: a newspaper home page has a site <header>, one <main> with several <section>s ("World news", "Politics"), and each section contains several <article>s. An article can itself contain sections.

⚡ Pro hackQuick landmark auditOpen browser DevTools, then the Accessibility panel, to see the accessibility tree. You will see banner, navigation, main, complementary and contentinfo appear straight from your tags. If they are missing, your page is div soup.
⚡ Pro hackLabel repeated landmarksTwo <nav> elements? Give each a name: <nav aria-label="Primary"> and <nav aria-label="Footer">, so screen readers can tell them apart.
✎ Notes corrected: the notes sometimes write <headers>; the element is <header> (singular). And "the holy grail layout" means header, main content, two sidebars, footer, and the markup order shown is correct for source order, with CSS handling positioning.
