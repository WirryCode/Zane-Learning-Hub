Tables

Structure, headers, captions, accessibility

A <table> shows tabular data: information that is compared, sorted, calculated or cross-referenced in rows and columns. A grid of thumbnails is not tabular data (use a list and CSS grid). Never use a table for page layout.

1. The parts of a table, in order

Every child is optional, but the order is fixed. The only two you should treat as required in practice are <table> itself and a <caption>.

<table>
  <caption>Workshop students</caption>
  <colgroup><col><col span="2"></colgroup>
  <thead><tr><th scope="col">Year</th><th scope="col">Name</th><th scope="col">Grade</th></tr></thead>
  <tbody>
    <tr><td>1956</td><th scope="row">Lou Minious</th><td>A</td></tr>
  </tbody>
  <tfoot><tr><td colspan="3">End of list</td></tr></tfoot>
</table>
ElementRoleNotes
<caption>The table's visible title and accessible nameFirst child. Move it with CSS caption-side, not the old align attribute
<colgroup> / <col>Styling hooks for whole columnsNo semantics. Only a few properties work (border, background, width, visibility)
<thead> <tbody> <tfoot>Row groups, implicit role rowgroupZero or more of each. Loose rows are wrapped in an implicit <tbody>
<tr>One rowContains <th> and <td> cells
<th>Header cell (role columnheader or rowheader)Association survives scrolling out of view
<td>Data cellGets its meaning from its headers
🧠 Remember itCCTTT: the table child orderCats Chase Tiny Tin Toys = caption, colgroup, thead, tbody, tfoot.
⚠ Common mistakeContent outside a cellPutting text or a <div> directly inside <table> or <tr> is invalid. The parser throws it out in front of the table. Content lives only in <td> or <th>.

2. Naming and describing a table

  • <caption> is the preferred name. It is visible to everyone, so users know the purpose before reading a cell.
  • aria-label or aria-labelledby on the <table> also give an accessible name, but nothing visible.
  • If the table "makes a point", add a short summary. Short: put it in the caption. Longer: summarise in the caption and put the full text in a paragraph linked with aria-describedby, or wrap the table in a <figure> with a <figcaption>.
  • <tfoot> once had to come right after <thead> in HTML 4. In modern HTML put it last, where a reader expects totals.

3. Header cells and scope

A <th> makes its row or column the header for the data cells. That is how a screen reader announces "1956, Year, Lou Minious" for a single cell. The scope attribute says which direction a header covers:

scopeMeaning
colHeader for the column below
rowHeader for the row to its right
colgroup / rowgroupHeader for a group of columns or rows (complex tables)
auto (default)The browser works it out from position

Simple tables work with defaults, but writing scope is cheap insurance for assistive technology.

⚠ Common mistakeBold td instead of thMaking a header row from <td> cells with bold CSS looks right and means nothing. No header association, nothing for screen readers. Use <th>.

4. Merging cells

  • colspan="n" merges a cell with the n-1 cells to its right, in the same row.
  • rowspan="n" merges a cell with the n-1 cells below it, set on the first cell of the merge.
  • A merged-over cell must be left out of the markup. Each row must still add up to the same number of columns.
  • When one cell has more than one header and scope cannot express it (merged headers, more than two levels), give every data cell a headers attribute: a space-separated list of the header cells' id values. It is valid on <td> and <th>.
  • Complex tables confuse everyone, not only screen reader users. Prefer several simple tables.
🧠 Remember itCARD: merge directionsChickens Always Rent Dinosaurs = Colspan goes Across, Rowspan goes Down.
☠ Major fail pointColspan miscountIf a row has too many or too few cells, the table skews: later cells shift into the wrong columns and every header association is wrong. Count the columns of each row after merging.

5. Styling tables

  • Spacing, borders and alignment are CSS: border-collapse, border-spacing (no effect when collapsed), padding, text-align, empty-cells: hide (separate borders only). The old cellpadding, cellspacing, border and align attributes are obsolete.
  • Paint order, bottom to top: table, column groups, columns, row groups, rows, then cells on top. <td>/<th> are not descendants of <col>, so they do not inherit its styles, and cell styles win.
  • Stripe rows with tbody tr:nth-of-type(odd). Beware nth-child on cells when some cells are merged: it counts the cells that exist in each row.
  • Tables are sized by their content and are not responsive by default.
  • If you change display on table elements, add the ARIA roles back (role="table", row, cell...). Some browsers drop table semantics when display changes.
⚡ Pro hackScrollable table on phonesWrap a wide table in <div role="region" aria-labelledby="cap" tabindex="0" style="overflow-x:auto"> and give the <caption> the id cap. Keyboard users can then focus the region and scroll it, and it keeps a name.
⚡ Pro hackSticky headerthead th { position: sticky; top: 0; background: #fff } keeps the header visible while a tall table scrolls. This is why <thead> exists as a styling hook.
☠ Major fail pointTables for layoutA table used for page layout makes screen readers announce rows and columns that mean nothing and breaks on small screens. Use CSS grid or flexbox. If you inherit a layout table, mark it role="none".

6. Choosing the right element

If the data needs a spreadsheet to present at a meeting, use a table (students and grades over three terms). If it would suit presentation slides, it is likely a description list (terms and definitions). A recipe's ingredients are a plain list.
