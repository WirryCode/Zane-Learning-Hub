Text Basics

Headings, paragraphs, quotes, entities

1. Headings: six levels, one outline

HTML gives you <h1> (most important) to <h6> (least). Think of a textbook: title, chapters, sections, sub-sections. Browsers size them largest to smallest by default, but size is not the point: the level is a statement about structure.

Browsers never implemented the once-planned "document outline" algorithm, and it was removed from the HTML specification. Screen reader users, however, jump through a page using headings (the H key), so a logical order is essential.

🧠 Remember itSTAIRS: heading rulesStart at h1, Take one step at a time, Always go down by one, Include one main h1, Reset levels by sectioning, Style with CSS, never with headings.
⚠ Common mistakeHeadings for looksUsing <h4> because it "looks the right size", or <h3> to make text bold. Choose the heading by structure, then resize it with CSS. For emphasis use <strong> or <em>.
☠ Major fail pointNested h1 shrinkingOld browsers shrank an <h1> nested inside <section> or <article>. Modern browsers removed those rules, and assistive technology never honoured them (a nested h1 was always "heading level 1"). Never rely on nesting to change a heading's level.

2. Paragraphs and line breaks

<p> marks a paragraph. The closing </p> is technically optional, but always write it: it prevents surprises, for example a <div> after an unclosed <p> silently closes it.

<br> inserts a line break within a block: addresses, poems, signature blocks. It is not a spacing tool. To separate paragraphs, close one <p> and open another; the gap is then controlled by CSS margins and is accessible.

⚠ Common mistakebr br brStacking <br><br> to create paragraph spacing, or using &nbsp; runs for indentation. Use <p> and CSS margin or padding.
⚡ Pro hackWhitespace collapsesHTML collapses runs of spaces and line breaks into one space. To preserve formatting (code, ASCII art, poetry) use <pre>, or CSS white-space: pre-wrap.

3. Quotations and citations

<blockquote>Block quote (long)No (indents it)Always required
<q>Inline quote (short)Yes, language-awareRequired

  • The author's name is not part of the quote, so it goes after the <blockquote>, usually in its own <p>.
  • The <cite> element holds the work (book, film, website, program), not the person.
  • The cite attribute (on <q> and <blockquote>) takes a URL. It is machine-readable only; users do not see it.
  • Putting lang on the quote's container tells the browser which quotation marks to use and helps voice assistants pronounce it.
🧠 Remember itBQC: pick the quote tagBig quote = Blockquote (block). Quick quote = Q (inline). Credit the Creation = Cite (title of work).
⚠ Common mistakeCite means author<cite>Jane Doe</cite> is wrong when naming the speaker. Cite the work (<cite>Smoothie Weekly</cite>). Also, do not add manual quote marks inside <q>: you will get double quotes.
⚡ Pro hackQuote marks on blockquote<blockquote> shows none by default. Add them with CSS: blockquote p::before { content: open-quote; }

4. Entities: writing reserved characters

Because < starts a tag, you must escape it to display it. A character reference starts with & and ends with ;.

You wantWriteName
<&lt;less than
>&gt;greater than
&&amp;ampersand
"&quot;double quote
©&copy;copyright
™&trade;trademark
(space)&nbsp;non-breaking space

There are over 2,000 named references, and every character has a numeric form: &#169; (decimal) or &#xA9; (hex). With <meta charset="utf-8"> you may type most characters directly (é, ©, 😀); you only must escape < and &.

☠ Major fail pointEntity typos&copyright; does not exist (the name is &copy;). A missing semicolon or wrong name prints as literal text. Remember: & + name + ;.
🧠 Remember itLAQ: always-escape trioLess-than &lt;, Ampersand &amp;, Quote (inside attributes) &quot; = "Let's Always Quote".
✎ Notes corrected: the notes say you "generally do not need" &gt;, " or &amp;. In practice, always escape &amp; in text and URLs (?a=1&amp;b=2): a bare & followed by letters can be read as the start of an entity. > and " are safe in plain text but " must be escaped inside a double-quoted attribute. Also, the notes call the nested-landmark exercise "Oceana"; the region is spelled Oceania.

5. Sections need a name to be landmarks

A <section> is only exposed as a region landmark when it has an accessible name. Link its heading with aria-labelledby:

<section id="about" aria-labelledby="about_heading">
  <h2 id="about_heading">What you'll learn</h2>
  <p>...</p>
</section>
⚡ Pro hackNot everything is a landmarkToo many landmarks create noise for screen reader users. Name only the big, important sections.
✎ Notes corrected: the notes' sample heading reads "What you'll earn"; the workshop teaches, so it should say "What you'll learn".
