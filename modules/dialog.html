Dialog

Modal and non-modal dialogs

The <dialog> element represents any dialog box or pop-up panel. A modal dialog interrupts the user and demands attention: only the dialog can be used until it is dismissed. A non-modal dialog lets the user keep working on the page behind it. Pop-ups are valid, but each one forces the user to stop what they are doing, so use them with care.

<dialog> brings its own semantics, keyboard behaviour and the HTMLDialogElement interface, so you no longer need a library or a pile of ARIA to build one.

  • The three methods: dialog.show() (non-modal), dialog.showModal() (modal), dialog.close().
  • Writing the open attribute in HTML shows the dialog as non-modal, with no backdrop and nothing inert. The source's phrase "modal-less" means non-modal.
  • dialog.open is a boolean that is true whenever the dialog is shown, modal or not; it does not tell you which. Do not toggle the open attribute by hand to open a modal; call showModal().
  • Calling showModal() on a dialog that is already open non-modally throws an InvalidStateError. Close it first.
  • Avoid opening a dialog without a user action. If you must, make sure focus returns sensibly when it closes.

2. Focus, inert and autofocus

  • When a dialog opens, focus moves to its first focusable element. An element with autofocus inside the dialog takes it instead. This is the one place where autofocus is recommended (see the Focus module): put it on the safe choice, like "Cancel" on a delete prompt.
  • autofocus inside a closed dialog does nothing on page load. It applies each time the dialog is opened. (The lab below leaves it off: browsers block autofocus inside sandboxed frames like the editor, and its first control, Cancel, gets focus anyway.)
  • With a modal, Tab cycles through the dialog only: everything outside is inert, as if pointer-events: none were set. Even the button that opened it stops reacting.
  • When any dialog closes, focus returns to the element that had it before. If you close a non-modal dialog from a button outside it, that may be somewhere odd.
  • The global inert attribute does the same job for any region; showModal() applies that deactivation for you without writing the attribute.
  • autofocus moves the Tab starting point: the controls before it are still reachable with Shift+Tab. They are not "skipped" for good.

3. Closing a dialog

  • Escape: closes a modal (and fires cancel first). It does not close a non-modal dialog, so always provide a visible close button. The spec does not require one, but treat it as required.
  • A form with method="dialog" (or a button with formmethod="dialog"): the dialog closes with no JavaScript. Validation still runs, unless novalidate/formnovalidate. The data is neither sent nor cleared.
  • dialog.close(): closes it from script. It may take a value: dialog.close("saved").
  • Newer browsers add dialog.requestClose() and a closedby attribute (any for click-outside, closerequest, none). Treat these as progressive enhancement.

4. returnValue and events

  • dialog.returnValue is a string describing why the dialog closed. Submitting a method="dialog" form sets it to the value of the submit button that was used (the source says name: wrong). <button value="toasty"> gives "toasty"; a button without value gives "". close("x") sets it too.
  • Events: cancel (Escape; cancelable) and close (after any close). Read returnValue inside close.
  • The close event does not bubble; attach it to the <dialog> itself.

5. Styling and ARIA

  • The backdrop is dialog::backdrop (::backdrop is a pseudo-element, not ::background). It only exists for modal dialogs, and also matches the backdrop of fullscreen elements. Example: dialog::backdrop { background: rgb(0 0 0 / .6); }.
  • Browsers apply default styles. Chrome, Firefox and Edge use color: CanvasText; background: Canvas; Safari uses black on white. Colour is set on the dialog itself, so it is not inherited from body or :root, and background-color is not inherited either. A dark page with a light-text body can give you invisible dialog text.
  • The implicit role is dialog. For a confirmation that needs a response (a destructive action, a session warning) use role="alertdialog".
  • Give it an accessible name: aria-labelledby pointing at visible text, or aria-label. You do not need aria-modal when using showModal().
  • Do not add tabindex to a <dialog>: it is not interactive and does not take focus; its contents do.
  • A page behind a modal can still scroll in some browsers. body:has(dialog[open]) { overflow: hidden } locks it.
⚡ Pro hackClick outside to closeA click on a modal's backdrop targets the <dialog> itself. dialog.addEventListener('click', e => { if (e.target === dialog) dialog.close() }) gives light dismiss. Keep padding on an inner wrapper, not the dialog, or clicks on the padding will count as outside clicks.
⚡ Pro hackRead the result in a one-time handlerdialog.addEventListener('close', () => handle(dialog.returnValue), { once: true }) right before showModal() turns a dialog into "await the choice" logic with no global state.
☠ Major fail pointDialog without a way outA non-modal dialog does not close on Escape, and a custom modal that cancels cancel traps keyboard users. Always provide a focusable close or Cancel button.
⚠ Common mistakeDialog for everythingA modal for a cookie banner, a tooltip or a menu is overkill. Use a non-modal dialog, the Popover API (popover attribute) or an inline panel for content that should not block the page.
