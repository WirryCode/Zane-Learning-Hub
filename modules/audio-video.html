Audio & Video

Media elements, tracks, captions

HTML can play sound and video with no plugin at all. <audio> and <video> embed a media player, either from a single src or from a list of <source> suggestions, and <track> adds timed text (subtitles, captions, descriptions). This module covers the markup, the attributes that matter, and how to keep media accessible.

1. The two elements

  • <video> and <audio> share one interface, HTMLMediaElement. <video> adds width, height and poster; <audio> has no visual area, so it has none of those.
  • <video> can play sound files, but use <audio> for sound-only media.
  • The closing tag is required, even when empty. Content between the tags is fallback, shown only by a browser that does not support the element. That is almost never today, so also put a visible link to the file or a transcript outside the player.
  • Children go in this order: <source> elements, <track> elements, then fallback content.
<video src="videos/machines.webm" poster="images/machine.jpg" width="640" height="360" controls>
  <p>Your browser cannot play this. <a href="videos/machines.webm">Download the video</a>.</p>
</video>

2. Several sources and codecs

Without a src on the media element, add one or more <source> children. The browser takes the first one it can play, top to bottom.

<video controls poster="images/machine.jpg" width="640" height="360">
  <source src="videos/machines.webm" type="video/webm; codecs=vp9,opus">
  <source src="videos/machines.mp4"  type="video/mp4">
  <track label="English" kind="subtitles" srclang="en" src="vtt/subtitles-en.vtt" default>
  <track label="Français" kind="subtitles" srclang="fr" src="vtt/subtitles-fr.vtt">
  <p>Watch the <a href="https://example.com/video">video on our site</a>.</p>
</video>
  • type is the media (MIME) type. It stops the browser downloading a file it cannot decode. Add a codecs parameter to be exact (video/webm;codecs=vp8,vorbis, video/mp4; codecs=avc1.4d002a is H.264 Main Profile level 4.2). Put the most efficient format first and the most compatible last.
  • <source> may also carry media (a media query), like <picture>.
  • Check support from JavaScript with el.canPlayType('video/webm'): it returns "", "maybe" or "probably".

3. Attributes that matter

AttributeWhat it does
controlsShows the browser's player UI (play, volume, seek, fullscreen). Boolean. Without it, and without script, users cannot play the media at all.
autoplayStarts playing by itself. Browsers usually ignore it unless the media is muted (or the user has interacted with the site).
mutedStarts silent. In HTML it only sets the initial state; in script, read and write el.muted.
loopRestarts when it ends, forever.
preloadA hint: none (fetch nothing), metadata (duration and dimensions only), auto (browser decides). The browser may ignore it.
poster(<video> only) An image shown until playback starts. It is not shown again after pausing.
playsinlinePlays inside the page instead of forcing fullscreen on iPhones.
width, heightUnitless pixels. They reserve space so the page does not jump when the video loads.
crossoriginNeeded when media or track files come from another origin and you use them from script or as tracks.
  • Match the poster's aspect ratio to the video's; a difference causes a reflow and repaint when the video loads.
  • Autoplaying media is generally a bad experience, even muted with controls.

⚠ Common mistakeWriting mute instead of mutedThe attribute is muted. <video mute> is an unknown attribute that does nothing, and the video autoplays loudly (or is blocked). The same goes for controls: it is a plain boolean, not "booleancontrols".

4. Tracks: timed text

<track> points to a WebVTT (.vtt) file. The file must be same-origin unless crossorigin is set, and should be served as text/vtt.

WEBVTT

00:00:01.000 --> 00:00:03.500
Welcome to the machine workshop.

00:00:04.000 --> 00:00:06.000
[dishwasher beeps]
kindContains
subtitlesTranslation or transcription of dialogue. Needs srclang.
captionsDialogue plus sound effects and speaker cues, for people who cannot hear the audio.
descriptionsText description of the visuals, for people who cannot see the video.
chaptersTitles for navigating the timeline.
metadataData for scripts. Never shown.
  • label is the name shown in the player's menu. Mark one track default to switch it on automatically.
  • Style the displayed text with the ::cue pseudo-element (and ::cue(b) to match tags inside the cue).
  • Captions help far more than the deaf community: noisy trains, no headphones, a quiet office, learners of a language.
  • Browsers display tracks on <video>. A plain <audio> has no screen, so provide a transcript on the page (or show cues yourself with script, as in the lab below).
🧠 Remember itSCDCM: the five track kindsSilly Cows Dance, Chickens Meow = Subtitles, Captions, Descriptions, Chapters, Metadata.
⚠ Common mistakekind="caption"The value is plural: captions (and descriptions). A misspelt kind falls back to metadata, so your text silently never shows.

5. Background video and accessibility

Design teams love a silent, looping video behind the hero text. Do it like this, and treat it as decoration only:

<video playsinline autoplay loop muted poster="images/machine.jpg" role="none">
  <source src="videos/machines.webm" type="video/webm">
  <source src="videos/machines.mp4" type="video/mp4">
</video>
  • role="none" and no fallback: it is purely decorative. Never convey information in a background video.
  • Strip the audio track from the file; a muted video that still ships audio wastes bandwidth.
  • WCAG 2.2.2 (Pause, Stop, Hide): anything that moves automatically for more than five seconds needs a way to pause it. A loop never stops, so always provide a pause control.
  • Respect prefers-reduced-motion: pause or hide the video for users who ask for less motion.
☠ Major fail pointAutoplaying looped video with no way to stop itFails WCAG 2.2.2, distracts people with attention or vestibular conditions, and drains mobile data. Provide a visible pause button, honour prefers-reduced-motion, and keep the file small.
☠ Major fail pointSpoken content with no captionsA video with dialogue and no captions or transcript excludes deaf users and fails WCAG 1.2. An audio-only podcast needs a transcript.

6. Custom controls with JavaScript

Keep controls in the HTML so the player still works if JavaScript fails. Only once your own button exists, remove it. Use play(), pause(), the paused property, and keep the button's text and aria-controls honest.

<button id="playPause" aria-controls="song"
        data-play-text="Play audio" data-pause-text="Pause audio">Play audio</button>
<script>
const btn = document.getElementById('playPause');
btn.addEventListener('click', () => {
  const media = document.getElementById(btn.getAttribute('aria-controls'));
  if (media.paused) { media.play(); btn.textContent = btn.dataset.pauseText; }
  else { media.pause(); btn.textContent = btn.dataset.playText; }
});
</script>
  • play() returns a Promise. If the browser blocks playback it rejects with NotAllowedError, so write media.play().catch(...).
  • Useful members: currentTime, duration, volume, muted, ended, playbackRate, and the events play, pause, ended, timeupdate, loadedmetadata.
  • Related APIs: TextTrack (cues), Media Capture and Streams plus MediaDevices (microphone, camera, screen recording), and the Web Audio API (processing live or recorded sound).
⚡ Pro hackCheap and polite mediapreload="metadata" loads only the duration; add #t=10,20 to a src to play just seconds 10 to 20; controlslist="nodownload" hides the download item; disablepictureinpicture turns off PiP. For a decorative clip use object-fit: cover and put the video behind text with CSS.
⚡ Pro hackCatch the autoplay blockvideo.play() returns a Promise: video.play().catch(() => showPlayButton()). If autoplay is refused, show a visible Play button instead of leaving a dead frame.
