HTML APIs

DOM interfaces, Storage, Fetch, observers, permissions

HTML elements are the nodes that make up the Document Object Model (DOM). Markup describes the page; APIs let JavaScript read and change it. This module covers the element interfaces that every node inherits, then maps the wider family of HTML-related browser APIs (storage, network, location, drag and drop, history, canvas, observers) and the permission rules that govern them.

1. The DOM and the accessibility tree

  • The DOM is an API for accessing and changing documents: a tree of nodes (elements, attributes, text) where some nodes can have children and others cannot. The middle letter is "Object": every node is a JavaScript object with properties, methods and events.
  • The browser builds a second tree, the accessibility tree, from the DOM plus computed style. It holds only what assistive technology needs (role, name, state): display: none and hidden nodes are absent, and unlabelled <div>s are generic. The "AOM" (Accessibility Object Model) is the name for APIs that would expose and modify it; ordinary developer tools show it in a separate accessibility panel, not in the Elements panel.
  • The Elements panel in dev tools shows the DOM, which may differ from your source: the parser fixes errors (missing <tbody>, misplaced tags) and scripts change it.

2. What element APIs give you

  • Attributes through properties: img.alt, a.href, input.value, details.open. Properties often reflect attributes, but not always (input.value is the current value, the value attribute is the default).
  • Layout information, read-only: el.offsetHeight, el.getBoundingClientRect(). It updates automatically when the viewport changes. Reading it forces the browser to calculate layout, so reading and writing in a loop slows the page (see the Performance module).
  • State: video.duration, video.currentTime, video.ended, form.checkValidity(), dialog.returnValue.

3. Element interfaces

Almost every element has an interface named HTML + group + Element in upper camel case: <a> is HTMLAnchorElement, <img> is HTMLImageElement, <td>/<th> share HTMLTableCellElement. The middle part has no strict pattern, and you do not need to memorise them: know they exist and look them up.

  • Over 30 elements have no interface beyond HTMLElement (<address>, <article>, <section>, <nav>, <header>, <footer>, <aside>, <hgroup>...). Others, like HTMLParagraphElement, exist but add nothing. An unrecognised tag such as <foo> is an HTMLUnknownElement.
  • Collections have interfaces too: HTMLCollection.namedItem(name) returns the first element whose id or name matches, or null.

4. The inheritance chain

EventTarget → Node → Element → HTMLElement → the specific interface (e.g. HTMLImageElement).

  • EventTarget gives addEventListener() and removeEventListener() to nodes and to Window.
  • Node is the base of every kind of node: firstChild, nextSibling, appendChild(), cloneNode(), parentNode, textContent. Element, Document and DocumentFragment inherit from it.
  • HTMLElement adds what all HTML elements share: hidden, title, dataset, style, click(), focus(), innerText, contentEditable.
  • Override rule: if a child interface defines a property or method with the same name as one it inherits, the child's version wins. Example: HTMLCollection.length is read-only, but HTMLOptionsCollection.length (the options of a <select>) can also be set, to resize the list.

// Crockford-style "walk the DOM": visit a node, then each child in turn
function walk(node, callback) {
  callback(node);
  node = node.firstChild;
  while (node) { walk(node, callback); node = node.nextSibling; }
}

5. Document and Window

  • Document (a Node) represents the loaded page: document.body, document.title, document.styleSheets, document.querySelector(), createElement(), location, lastModified, cookie. document is an instance of HTMLDocument, which inherits from Document. HTMLDocument is the old name for the HTML-specific document.
  • Window is the global object of one tab (every tab has its own). It is the home of things that are not the DOM tree: devicePixelRatio, innerWidth, location, history, localStorage, timers, and constructors such as Worker. window.resizeTo() only works on windows opened by script, so on a normal tab it does nothing.
  • Collections: getElementsByClassName and children return live HTMLCollections that update as the DOM changes. querySelectorAll returns a static NodeList (it has forEach, but not map).
  • Set text with textContent (safe, fast). Using innerHTML with user-supplied strings enables cross-site scripting (XSS).
  • Element.shadowRoot leads to a ShadowRoot (see the previous module).

7. Secure contexts and permissions

  • Powerful APIs work only in a secure context: HTTPS, or localhost while developing. Check with window.isSecureContext. On plain HTTP, geolocation, service workers, the async Clipboard API and camera access are simply unavailable.
  • Many also need the user's permission, usually asked after a user gesture (a click): geolocation, notifications, camera and microphone, clipboard read. Permission can be denied, or blocked by a Permissions-Policy header or the allow attribute of an iframe.
  • Always handle the denied and unsupported cases. Ask for a permission when the user takes an action that needs it, not on page load. navigator.permissions.query({name:'geolocation'}) reports the current state without prompting.
  • Feature-detect: if ('geolocation' in navigator), not browser sniffing.
