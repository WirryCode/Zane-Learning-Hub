Attributes

Global and boolean attributes, data-*

Attributes are space-separated names and name/value pairs in the opening tag that add information and behaviour to an element. Some are global (any element), some are shared by several elements, some belong to one element only.

<a href="#register" target="_self">Registration</a>
<!-- href and target are attributes; the closing tag never has any -->

1. Syntax and case

  • Every attribute needs a value, except boolean ones (and, to a degree, enumerated ones).
  • A value containing a space or special characters must be quoted. Always quote: it is safer and easier to read.
  • HTML is not case-sensitive, but some values are. Values defined by the spec (type="Text") are case-insensitive. Strings you invent (id, class) are case-sensitive, in HTML, in CSS attribute selectors and in JavaScript.
<input type="text">   <input type="TEXT">   <!-- same -->
<div id="myId">       <div id="MyID">       <!-- different -->

2. Boolean attributes

If a boolean attribute is present, it is true. If absent, it is false. The value is irrelevant: even disabled="false" is still disabled.

<input required>
<input required="">
<input required="required">   <!-- all three identical, all valid -->

Examples: autofocus, inert, checked, disabled, required, readonly, multiple, selected, reversed, allowfullscreen, default, loop, autoplay, controls, muted. To turn one off, remove the attribute. Do not set it to "false".

el.removeAttribute("muted");    // off
el.setAttribute("muted", "");   // on (setAttribute needs two arguments)
el.toggleAttribute("muted");    // flip it
🧠 Remember itPIT: boolean rulePenguins Imitate Tigers = Present Is True. Absent is false. The value never matters.
⚠ Common mistakedisabled="false"It does not enable the control. The attribute is present, so it is true. Remove it, or set the DOM property el.disabled = false.

In XML languages such as SVG, every attribute needs a value, booleans included.

3. Enumerated attributes

Enumerated attributes accept a fixed list of keywords. They look like booleans but are not: absent does not mean false, and missing or invalid values fall back to a default that depends on the attribute.

4. Global attributes

More than 30 attributes work on any element, even in the <head>, though some do nothing there (hidden on <meta>). The important ones:

id

  • Must be unique in the document, with no spaces. Start with a letter and use ASCII letters, digits, _ and -. Pick a naming convention: ids are case-sensitive.
  • Uses: link target (href="#about"), script hook, <label for>, ARIA references, a high-specificity CSS hook (#about, or [id="about"] for lower specificity).
  • A duplicate id will not crash the page, but links, labels and scripts will pick the wrong element.
  • The fragment after # is never sent to the server. href="#" or href="#top" scrolls to the top for free.
  • document.getElementById("x") or querySelector("#x").

<label for="x"> matches id="x". Clicking the label focuses the control. A control may have several labels, but one label serves exactly one control. Nesting the control inside the label (implicit label) needs no for/id. aria-labelledby, aria-describedby, aria-details and aria-owns take a space-separated list of ids; aria-activedescendant takes one. If a control has both a <label> and aria-labelledby, the ARIA name wins.

class and style

  • class is only a hook for CSS and JS. Often unnecessary: good semantic structure lets you select by element, attribute and position. getElementsByClassName() returns a live list, querySelectorAll() a static one.
  • style holds declarations only (no at-rules, no keyframes, no pseudo-elements). It is legal but discouraged; use it for quick tests, then move the rule to a stylesheet.

tabindex and role

  • tabindex="0": focusable and in the natural tab order. tabindex="-1": focusable by script or click, but not tabbable. tabindex="1" or more: jumps the queue, chaos, avoid.
  • role comes from ARIA. It tells assistive tech what a widget is, but never changes behaviour: <span role="button"> is not a button.
🧠 Remember itFTB: tabindex valuesFrogs Tap Banjos = -1 Focusable, 0 Tabbable, positive Bad.

contenteditable

contenteditable makes any element editable, focusable and tabbable (like tabindex="0"). Read the current state with the property el.isContentEditable, not el.contentEditable (a string that is always truthy).

⚡ Pro hackA CSS editor in HTMLA <style contenteditable> set to display:block becomes a live editor: edit the text and the page restyles instantly. Handy for demos and for testing a rule.

5. Custom data attributes

  • Name: data- then at least one lowercase character, no colon (and no leading xml). data-birthday is valid. birthday and data:birthday are not.
  • Safe from clashes with present and future attributes. Browsers never give them default behaviour.
  • JavaScript: el.dataset is a DOMStringMap. data-first-name becomes el.dataset.firstName (kebab-case to camelCase). Values are always strings.
  • CSS can match them: [data-role="student"] { ... }.
⚠ Common mistakeUppercase in data namesHTML lowercases attribute names, so data-firstName becomes data-firstname and dataset.firstName is undefined. Write data-first-name.
⚡ Pro hackCounting with datasetel.dataset.count = Number(el.dataset.count) + 1 updates the attribute too, and [data-count="3"] in CSS reacts to it.
☠ Major fail pointInventing plain attributes<div status="open"> is invalid. Browsers tolerate it, but a future standard may give status a meaning and break your page. Always prefix with data-.
☠ Major fail pointDuplicate idsCopy-pasting a component twice gives two id="email" inputs. The second label focuses the first input, and getElementById returns the first one only. Ids are unique per document.
